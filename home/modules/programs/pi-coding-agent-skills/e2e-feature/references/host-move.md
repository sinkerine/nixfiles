## Resume after a host move

`e2e-dispatch` moves a running run between hosts. It freezes the old orchestrator and its subagents, moves the branch, the uncommitted work, and `<run dir>` with paths rewritten for this host, and then starts you with `/skill:e2e-feature resume <handoff file>`. The old orchestrator, its goal, and its subagent runs are gone, and their run ids do not work here.

1. **Orient.** Read the handoff file, a JSON record of the move: the feature, the two hosts, `home` (the host that delivers the run), the branch, the plan path, the accepted task commits, the subagent steps that were in flight, and the path of a copy of the old transcript. Redo the Feature worktree record for this worktree; it reuses the copied `<run dir>` and `snap.sh`, and its `e2e-dispatch register` step records you. Run `e2e-feature-run init --feature <feature>` to restore the host-local explicit scheduling settings before creating the new goal; this never resumes a user pause. Do not create a worktree, a design tab, or a new plan.
2. **Rebuild the state** from `<run dir>/tasks.md`, `<run dir>/rulings.md`, the findings files, the `<feature>: <task id>` commits in `git log`, and `git status`; the uncommitted work moved with the run. Preserve the distinction between implemented and accepted tasks, plus consolidated review scope coverage and round counts. Do not infer acceptance from a provisional checkpoint commit. Revalidate moved gate input/environment identities before reusing evidence. Search the transcript copy only for details those files lack, and never read it whole.
3. **Restart tracking.** Create a new workflow mission, and a new execution goal as in Execution goal whose objective says it continues a moved run. If `previousGoals` in the handoff shows a paused goal, the user paused this run before the move: create the goal, then call `ask_user` to ask whether to continue before doing any work.
4. **Restart the steps that were in flight:** an implement step as a fresh worker told to continue from the task's current files, a review round from its start, and a fix round as a fresh worker given the same findings file. Then continue the workflow from where it stands.
5. **Away from home.** On a host other than `home`, do not merge into the default branch, push, or archive the workspace. When only delivery remains, or the E2E instructions need something this host lacks, such as an emulator, devices, or a display, stop and call `ask_user` with `<feature> is ready to go home: run e2e-dispatch back <feature> here or on <home> (home must be awake and reachable).` Waiting in `ask_user` costs nothing, while ending the turn would only wake you again. Once back on `home`, deliver as usual.
